# Sub-Phase 2.5: Event-Based Recovery & Contingency Fee Ledger Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the append-only `recovery_events` ledger, deterministic 20% contingency fee engine (`fee_events`), and automated fee `invoices` billing pipeline.

**Architecture:**
1. Recovery ledger & fee engine service (`apps/api/app/services/recovery_ledger_service.py`) performing immutable recovery event recording, 20% contingency fee math (`Fee = Eligible Recovered × 0.20`), and automated invoice generation.
2. REST API router endpoints in `apps/api/routers/claims.py` (`POST /api/claims/{claim_id}/recovery/record`, `GET /api/claims/{claim_id}/ledger`).
3. Comprehensive Pytest TDD suite (`apps/api/tests/test_recovery_fee_ledger.py`) verifying contingency fee math, $0 recovery edge case, and ledger immutability.

**Tech Stack:** Python 3.11/3.14, FastAPI, SQLAlchemy, Alembic, Supabase PostgreSQL.

---

## Global Constraints

- Contingency fee MUST be calculated deterministically in Python: `round(eligible_amount * contingency_rate, 2)`.
- If `eligible_amount` is `0.0`, fee MUST be `$0.00`.
- Recovery ledger records (`recovery_events`) MUST be immutable (append-only).

# Sub-Phase 2.2: Follow-Up Automation & Carrier SLA Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement 30-day acknowledgment and 120-day resolution statutory SLA tracking engines under 49 CFR § 370.9, automated citation-grounded follow-up draft generation, and human-in-the-loop server-side dispatch guards.

**Architecture:**
1. Deterministic SLA calculation service (`apps/api/app/services/sla_service.py`) computing Carmack & 49 CFR § 370.9 deadlines.
2. Follow-up draft generation and human sign-off state machine (`apps/api/app/services/followup_service.py`).
3. REST API endpoints in `apps/api/app/routers/claims.py` providing SLA telemetry and draft approvals.
4. Comprehensive Pytest TDD suite (`apps/api/tests/test_sla_engine.py`) verifying boundary conditions and 403 server guards.

**Tech Stack:** Python 3.11/3.14, FastAPI, SQLAlchemy, Alembic, Supabase PostgreSQL.

---

## Global Constraints

- Follow-up communications must be generated in `draft_status = 'DRAFT'` state.
- Attempting to dispatch a follow-up without human sign-off returns `HTTP 403 Forbidden`.
- SLA deadline math must use exact calendar days (`timedelta(days=30)` and `timedelta(days=120)`).

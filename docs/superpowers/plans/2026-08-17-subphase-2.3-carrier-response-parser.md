# Sub-Phase 2.3: Carrier Response Intelligence & Settlement Extraction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement inbound carrier response ingestion, VLM/OCR extraction of offer amounts, decision types (`ACCEPTANCE`, `PARTIAL_SETTLEMENT`, `DENIAL`), denial reason codes, and settlement discrepancy calculations.

**Architecture:**
1. SQLAlchemy domain model `CarrierResponse` (`apps/api/app/models/domain_models.py`) storing extracted settlement offers, carrier claim reference numbers, and reason codes.
2. Extension of `DocumentParser` abstraction (`apps/api/parsers/carrier_response_parser.py`) parsing carrier letters with confidence scoring.
3. Carrier response processing service (`apps/api/app/services/carrier_response_service.py`) calculating settlement deltas (`claimed_amount - offer_amount`).
4. Comprehensive TDD test suite (`apps/api/tests/test_carrier_response_parser.py`) verifying money-critical parsing and fixture extractions.

**Tech Stack:** Python 3.11/3.14, FastAPI, SQLAlchemy, Alembic, Pydantic v2.

---

## Global Constraints

- Extraction must validate into Pydantic schema with confidence scoring.
- Money-critical fields (`carrier_offer_amount`, `disputed_amount`) must be computed deterministically in Python.
